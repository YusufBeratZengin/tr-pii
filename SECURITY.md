# Security Policy

`tr-pii` is an offline privacy library designed to detect and mask Turkish personal data (PII) before text is sent to third-party services, logs, or LLMs.

## Supported Versions

Only the latest released version receives security updates and bug fixes.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Security Vulnerability or Detection Bypass

Please do **not** open a public issue for security vulnerabilities, detector bypasses, or missed detections that could expose personal identifiers.

Instead, report them privately using GitHub's Private Vulnerability Reporting:

> **Report privately**: <https://github.com/YusufBeratZengin/tr-pii/security/advisories/new>

When submitting a report:
- **Never include real personal identifiers** (no real TCKN, phone numbers, IBANs, or customer records). Always demonstrate the bypass using synthetic, checksum-valid identifiers (such as those generated by `tr_pii.fake`) or dummy test strings.
- Provide step-by-step reproduction instructions and minimal test cases.
- Specify the affected library version and runtime environment.

You can expect an initial acknowledgement within one week. Once verified, fixes are prepared and released as soon as possible, with credit in the changelog (unless requested otherwise).

## Scope and Local Processing Guarantee

`tr-pii` is strictly zero-dependency and performs all detection and masking locally in memory. It makes no network requests, includes no telemetry or analytics, and does not store input text to disk unless explicitly directed via CLI output options.
